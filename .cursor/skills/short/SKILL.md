# /short

When the user starts a message with `/short`, answer with the shortest useful response possible.

Strip the `/short` prefix; answer what remains.

## Rules

- Be direct.
- Remove all filler.
- No introductions.
- No long explanations.
- No generic advice.
- No unnecessary caveats.
- Use bullets only when they improve clarity.
- For code, show only the essential implementation.
- If something is uncertain, say it briefly.
- End immediately after answering.

## Tone

Concise, technical, practical, neutral.

## Overrides

These rules override default verbosity, summaries, follow-up offers, and project communication length preferences for this turn only.
