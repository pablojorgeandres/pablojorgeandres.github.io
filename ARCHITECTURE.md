# Nimú — Architecture

Static vanilla storefront (dietética). No framework, no build, no `package.json`.

## Stack

| Layer | What |
|-------|------|
| Frontend | `index.html` + `styles.css` + shared `js/*` |
| Dashboard | `dashboard.html` + `dashboard.css` + `js/dashboard.js` |
| Catalog | Static JSON under `data/` (GitHub Pages) |
| Source of truth | Google Sheets (1 spreadsheet per place) |
| Backend | Google Apps Script (`resources/*.js` → copy into GAS editor) |
| Checkout | WhatsApp (`wa.me`) + background order POST to Sheets |

Local preview needs an HTTP server (`python3 -m http.server 8000`). `file://` breaks `fetch('data/...')`.

## Repo map

```
index.html                 # Storefront
dashboard.html             # Back office (login + clients + remito + slider)
dashboard.css
styles.css
js/
  config.js                # STORE, URLs, zones, fmt
  catalog.js               # static JSON fetch + cache + product code index + slider fetch
  orders-api.js            # postOrderToSheet + fetchOrdersApi (ORDERS_URL)
  slider-api.js            # postSliderToSheet + JPEG compress (APPS_SCRIPT_URL)
  slider.js                # storefront place carousel
  whatsapp.js              # customer→store + remito→client wa.me builders
  dashboard.js             # dashboard UI/state
data/
  places.json              # [{id,name}] — only file always in clone
  {placeId}/categories.json          # generated by publisher
  {placeId}/products/{slug}.json     # generated by publisher
  {placeId}/slider.json              # place home slider manifesto
imgs/slider/{placeId}/     # slider images 1.jpg … 7.jpg (overwrite in place)
resources/
  appscript.js             # Catalog API + CacheService + slider doPost + legacy doPost
  appscript-publish.js     # Sheets → GitHub JSON + binary GitHub helpers
  appscript-pedidos.js     # Orders writer + clients/orders doGet (ORDERS_URL)
```

`imgs/` and most of `data/{place}/` may be missing locally until publisher runs / Pages deploy.

## Data flow

```
Google Sheets (tabs = categories)
        │
        ├─ publishCatalog() ~1h ──► GitHub data/*.json ──► fetch() ──► UI
        │
        └─ doGet ?action=search ─────► APPS_SCRIPT_URL ──► global search

Cart → WhatsApp (primary UX)
     └─ form POST orderData (iframe) → ORDERS_URL
            ├─ findOrCreateClientCode_ → Contacts sheet (DB CONTACTS SF/BA)
            └─ append order rows (con CodCliente) → Orders spreadsheet

Dashboard → GET ORDERS_URL?action=clients|orders
         → POST remito (orderData + customer.clientCode) → WhatsApp to client phone
```

### Sheet schema

- Tabs = categories; tabs starting with `_` ignored.
- Columns: `id`, `name`, `imageUrl`, `description`, `variants`
- Cover row: `id=_cover` or `name=categoryimage` (not a product)
- `variants`: JSON array `[{label, price, code}]`

## Dashboard

- URL: `/dashboard.html` (login client-side: user `Anto`, session in `sessionStorage`).
- Views: clientes (filtro lugar + búsqueda), detalle + pedidos, remito manual, **slider** (por lugar).
- Slider: máx. 7 slots; imágenes en `imgs/slider/{place}/{n}.jpg` (overwrite); manifiesto `data/{place}/slider.json`; links `none` | `category` | `external`. Escritura vía `ORDERS_URL` (`appscript-pedidos.js` + GitHub Contents API). Requiere `GITHUB_TOKEN` en Script Properties del **proyecto de pedidos** y redeploy del Web App.
- Remito: arma ítems por código de catálogo → POST `orderData` (con `customer.clientCode` si existe) → `wa.me` al teléfono del cliente (o el que carga Anto).
- Auth v1 is **not** secure (hardcoded credentials); harden later.

## Apps Script (`resources/`)

Source in repo is **not** auto-deployed. Edit in Google, keep `resources/` in sync.

### A — `appscript.js` (catalog API)

`doGet` actions: `places` | `categories` | `products` | `search` | `slider` | legacy `grouped=true`.

Server cache: `CacheService`, **TTL 300s**.

Keys: `categories_v1_{place}`, `products_v1_{place}_{category}`, `search_v1_{place}_{q}`, `catalog_v3_{place}_g`.

`doPost`:
- **Slider editor:** form field `sliderData` (`op`: `upsert` | `meta` | `remove`) → GitHub PUT/DELETE + update `data/{place}/slider.json`; responde HTML + `postMessage` (`source: nimu-slider`).
- **Legacy** orders into each place’s catalog sheet (frontend de pedidos **no** usa este path).

**Deploy (manual):** after changing slider helpers / `doPost`, paste `appscript.js` + `appscript-publish.js` into the catalog GAS project and **redeploy** the Web App (keep `APPS_SCRIPT_URL`).

### B — `appscript-pedidos.js` (orders + dashboard reads)

Active writer/reader for `ORDERS_URL`.

**`doPost`:** reads `e.parameter.orderData`, returns HTML that `postMessage`s to parent.

On each order:
1. If `customer.clientCode` / `codCliente` is a valid `S#`/`B#`, use it (optionally fill empty contact phone). Else `findOrCreateClientCode_` — match phone then name; else append next code.
2. Write order rows with **CodCliente** after Fecha.

**`doGet`:**
- `action=clients&place=` → contacts list
- `action=orders&place=&clientCode=` → parsed order blocks (optional `q`)
- `action=slider&place=` → reads `data/{place}/slider.json` from GitHub

**`doPost`:**
- `orderData` → orders (unchanged)
- `sliderData` → GitHub upsert/meta/remove for place slider (`source: nimu-slider`)

Read cache: `CacheService` ~90s (`clients_v1_*`, `orders_v1_*`).

Order columns: `Fecha y Hora`, `CodCliente`, `Nombre`, `Teléfono`, `Dirección`, `Zona`, `Lugar`, `Notas`, `Detalle Producto`, `Codigo Producto`, `Cantidad` (sin DNI).

**Deploy (manual):** paste updated script into GAS project → ensure edit access to contacts sheet → set `GITHUB_TOKEN` (for slider) → redeploy Web App version (keep `ORDERS_URL` if updating same deployment). Required after adding `doGet`/`sliderData` for the dashboard.

### C — `appscript-publish.js` (static publisher)

Same GAS project as A. `publishCatalog()` → GitHub Contents API.

Script properties: `GITHUB_TOKEN`, `GITHUB_REPO` (default `pablojorgeandres/tienda-nimu`), `GITHUB_BRANCH` (default `main`).

Writes (catalog): `data/places.json`, `data/{place}/categories.json`, `data/{place}/products/{slug}.json`.

Also exposes helpers used by the slider editor: `commitBase64File_`, `deleteFile_`, `readGithubTextFile_`.

## Cache (faster loads)

### Browser `localStorage` — 24h

`CACHE_EXPIRY_MS = 24h`. Helpers in `js/catalog.js`: `setCacheWithExpiry` / `getCacheWithExpiry`.

| Key | Content |
|-----|---------|
| `categories_v2__{placeId}` | categories object |
| `products_v2__{placeId}__{category}` | product array |

`clearCatalogCache()` / storefront `clearCache()` removes keys starting with `categories_`, `products_`, `catalog_`.

Other LS (not catalog TTL): `cart`, `deliveryZone__{placeId}`, `nim_cart_important_*`.

Search is **not** cached client-side.

### Apps Script `CacheService`

- Catalog API: **5 min** (search etc.).
- Orders reads: **~90s** (`clients_v1_*`, `orders_v1_*`).

### Static JSON on GitHub

Implicit CDN. Publisher ~1 h. Client 24h cache can hide fresher publishes until expiry / `clearCache()` / key bump.

### Images

Drive URLs normalized to thumbnails; lazy backgrounds via `IntersectionObserver` (`LAZY_BG_ROOT_MARGIN = 150px`).

Place home slider: static files under `imgs/slider/{place}/` referenced by `data/{place}/slider.json` (`?v=` cache-bust).

## Gotchas

1. README is partly outdated (`PRODUCTS_URL` / PWA / open without server — ignore).
2. Frontend orders go **only** to `ORDERS_URL` (`appscript-pedidos.js`), not catalog `doPost`.
3. Incomplete local clone: missing generated JSON / `imgs/` is normal.
4. Category tab names are case-sensitive; slug is filename only.
5. WhatsApp is primary; sheet save is best-effort (`console.warn` on fail).
6. No service worker / PWA despite older README claims.
7. Bump cache key version (`v2` → `v3`) to force clients to refetch after breaking catalog changes.
8. Dashboard clients/orders need a **redeploy** of the pedidos Web App after updating `appscript-pedidos.js`.
9. Dashboard slider uploads need a **redeploy** of the **pedidos** Web App after updating `appscript-pedidos.js`, plus `GITHUB_TOKEN` (and optional `GITHUB_REPO` / `GITHUB_BRANCH`) in that project’s Script Properties.
